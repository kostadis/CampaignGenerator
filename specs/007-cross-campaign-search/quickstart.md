# Quickstart: Cross-Campaign Provenance-Aware Search Seam

**Feature**: `007-cross-campaign-search` | **Date**: 2026-08-05

Runnable validation scenarios that prove the feature works end to end. Each maps to a
Success Criterion or a User Story's Independent Test in [spec.md](./spec.md). Schemas live
in [contracts/](./contracts/); field semantics in [data-model.md](./data-model.md).

## Prerequisites

```bash
# 1. The workspace, with the two authored documents in place (Phase 0)
ls ~/src/campaigns/provenance.yaml
ls ~/src/campaigns/*/docs/corrections.yaml          # expect 6

# 2. Editable install into the venv the tools run under (repo CLAUDE.md).
#    Required after ANY [project.scripts] change — this feature adds two.
uv pip install -e . --python "$VIRTUAL_ENV/bin/python"

# 3. Verify both console scripts resolved
which provenance provenance_mcp

# 4. ripgrep is OPTIONAL but strongly preferred (~60x). Confirm Python can see it —
#    a shell alias is not enough; the MCP server is spawned with an inherited PATH.
python -c "import shutil; print('rg ->', shutil.which('rg'))"    # expect /usr/bin/rg
rg --version                                                      # expect 15.1.0+
```

If `shutil.which("rg")` prints `None`, everything below still works via the stdlib
fallback — slower, and `capabilities` will say so.

`ANTHROPIC_API_KEY` is **not** required. This feature makes no LLM call (FR-033); if
anything here asks for a key, that is a bug.

## Scenario 0 — the authored data is valid (Phase 0 exit)

```bash
provenance check
```

**Expect**: exit `0`; each of the six campaigns validated; `stormgiants` and `Hillsfar`
listed with the informational finding `no-identity-store`. Any `tier-ambiguous` or
`stale-correction-entry` finding is for the GM to rule on, not for the tool to fix.

**Negative test — FR-030 fails loudly, not partially:**

```bash
cp ~/src/campaigns/provenance.yaml /tmp/pv.bak
printf '\n  bogus_key: 1\n' >> ~/src/campaigns/provenance.yaml
provenance check; echo "exit=$?"          # expect exit=3, LOAD ERROR naming the key
cp /tmp/pv.bak ~/src/campaigns/provenance.yaml
```

A partial load — five good campaigns served, one silently skipped — is the failure FR-030
exists to prevent. Exit `3` with a pydantic path, never exit `0` with a shortened list.

## Scenario 1 — Story 1's Independent Test (P1, the MVP)

```bash
provenance search "Woodland Manse" --campaign Phandalin --limit 5
```

**Expect**:

1. The `docs/world_state.md` hit is tagged `WORKING REFERENCE`, `GENERATED BY distill`, and
   `KNOWN STALE` with the `woodland-manse-empty` correction text **inside the hit's frame**
   (FR-004 — not in a footer).
2. The `docs/chapters/chapter_43_*.md` hit is tagged `AUTHORITATIVE` and ranks **above** the
   generated hit at equal relevance (FR-010).
3. No hit is bare text (FR-001).

> **Read this before judging the output.** `docs/world_state.md` was regenerated on
> 2026-08-05 and no longer contains the stale sentence — the file now says the Manse *was*
> cleared. The correction still attaches, because corrections match on **path and subject,
> never on the stale text** (research [D12](./research.md#d12)). That is the behaviour under
> test here: a correction must not silently stop applying when a generated file is rewritten.

## Scenario 2 — SC-001, envelope completeness across the whole corpus

```bash
for c in Phandalin out-of-the-abyss stormgiants toee Hillsfar obelisk; do
  provenance search "the" --campaign "$c" --limit 200 --json \
    | python -c '
import json,sys
REQUIRED = {"campaign","path","line","excerpt","excerpt_encoding","context_before",
            "context_after","tier","tier_ambiguous","generated_by",
            "generated_but_hand_edited","chapter","provenance_range","corrections",
            "corrections_status","matched_surface_form","relevance","horizon_disposition"}
hits = json.load(sys.stdin)["hits"]
bad = [h["path"] for h in hits if set(h) != REQUIRED]
print(f"{len(hits):4d} hits, {len(bad)} with a wrong key set")
sys.exit(1 if bad else 0)'
done
```

**Expect**: `0 with a wrong key set` for all six. SC-001 is a statement about the **key
set**, not about spot-checked fields — a field with nothing to say carries `null`, never
omission.

## Scenario 3 — SC-003, no input searches everything

```bash
provenance search "Woodland Manse";                    echo "exit=$?"   # expect 1
provenance search "Woodland Manse" --campaign "";      echo "exit=$?"   # expect 1
provenance search "Woodland Manse" --campaign all;     echo "exit=$?"   # expect 1
provenance search "Woodland Manse" --campaign '*';     echo "exit=$?"   # expect 1
```

**Expect**: all four refused, exit `1`, each message enumerating the six known campaigns.
`all` and `*` are refused as **unknown campaign names** — they are not tokens, and there is
no `--all-campaigns` flag in increment 1 (contracts/cli.md).

`grep -rn 'campaigns.*=.*\[\]\|campaigns.*=.*None' provenance/` should find no default for
the scope parameter anywhere in the stack — the refusal is structural, not defensive.

## Scenario 4 — SC-005, suppression is always counted

```bash
provenance search "Grannoc" --campaign Phandalin --tier authoritative
```

**Expect**: when the filter excludes everything, the answer is
`ALL N HITS SUPPRESSED BY TIER FILTER` with a per-tier breakdown — never an empty result
set (FR-011). Repeat with `--horizon 20` for FR-012's excluded count.

Every response also prints `excluded by manifest exclude globs: N`, including when `N` is
`0`. Verify it moves:

```bash
provenance search "Ilvara" --campaign out-of-the-abyss --json | python -c \
  'import json,sys; r=json.load(sys.stdin); print("excluded:", r["suppressed_by_exclude"])'
```

**Expect** a number matching the count of files the campaign's `exclude` globs removed. If
this always reads `0` regardless of the manifest, the counter is not wired and the last
silent scope narrowing is still open (research [D17](./research.md#d17)).

## Scenario 5 — Story 2's Independent Test (P2), all three identity states

```bash
provenance resolve Ilvara   --campaign out-of-the-abyss   # RESOLVED → Ilvara Mizzrym
provenance resolve Topsy    --campaign out-of-the-abyss   # RESOLVED + "DISTINCT from Turvy"
provenance resolve Vera     --campaign obelisk            # NOT FOUND IN IDENTITY STORE
provenance resolve Harshnag --campaign stormgiants        # NO IDENTITY STORE (SC-006)
```

**Expect** the three states never collapsed: `not-found` (store exists, form absent) and
`no-store` (campaign has none) are different answers to different questions
(FR-017/FR-018). Every response prints
`known-wrong variants: NOT RECORDED BY SCHEMA` — the entity registry has no such field, so
the caller learns the distinction is unavailable rather than reading an empty list as
"there are none" (research [D10](./research.md#d10)).

> **`Vera` returning `NOT FOUND` is the correct, passing result — not a bug.** Verified
> 2026-08-05: obelisk's registry has no Veyra entry (though `obelisk/characters/veyra.md`
> exists), and no registry in any campaign contains Kazneporium or Kostadinious. FR-032
> forbids this feature from writing identity data; making those two pairs resolve is a GM
> action via `registry alias` / `registry mark-distinct`. Story 2's AS-1 and AS-2 are
> therefore proven by contract tests over pinned fixtures, and here on the live corpus by
> the real recorded confusions (research [D11](./research.md#d11)).

Alias expansion:

```bash
provenance search Ilvara --campaign out-of-the-abyss --expand-aliases --limit 10
```

**Expect**: hits matching `Mistress Ilvara` appear, each carrying its own
`matched_surface_form` (FR-019).

## Scenario 6 — SC-002, the five documented incidents

```bash
python -m pytest tests/test_provenance_incidents.py -v
```

**Expect 4 of 5 here**, plus incident 5 in `tests/test_provenance_identity.py` — SC-002's
five span two mechanisms. Incidents 1–4 are corrections-backed; **incident 5 is an identity
matter** (`contracts/corrections.md`, "Incident 5") covered by T051/T052.

Each asserts that the misleading source is labeled such that a reviewer identifies it as
stale **without opening the file** — which is what SC-002 literally requires. Incident 1's
text has drifted since the spec was written, so it asserts against a pinned fixture for the
mechanism plus the live corpus for the envelope.

**Incident 3 asserts something different on purpose.** The Sequioa/Zephyr species swap is
not reproducible in `toee/docs/party.md` as of 2026-08-05 — Zephyr has a species, Sequoia
has none, "fire resistance" appears only as a potion, and toee has no `characters/`
directory to check against. Its entry therefore ships `verified: false`, and the test
asserts it **surfaces as unverified rather than as settled fact**, and that
`provenance check` reports it as an `unverified-correction` finding for the T031 gate.

```bash
provenance check --campaign toee | grep unverified-correction
```

Incident 2 is the richest live case:

```bash
provenance search Calmer --campaign toee --limit 5
```

**Expect** the `docs/npcs/calmer.md` hit tagged `WORKING REFERENCE`,
`GENERATED BY planning`, `generated_but_hand_edited: true`, and carrying the
`calmer-alive-undercover` correction. The file simultaneously says `**Status:** Dead.`
(line 40) and carries a hand-written banner saying he is alive (lines 4–6) — the spec's
"generated **and** hand-edited afterward" edge case, live in the corpus, where the next
`planning --build-dossiers` run destroys the human's note.

## Scenario 7 — SC-007, latency, and scanner parity

```bash
# Which scanner is active?
provenance capabilities | grep -A2 'literal'      # expect: impl=rg 15.1.0 (/usr/bin/rg)

for s in rg python; do
  echo "--- $s ---"
  for i in $(seq 20); do
    /usr/bin/time -f %e provenance search "Ilvara" --campaign out-of-the-abyss \
                        --limit 50 --scanner $s
  done 2>&1 >/dev/null | sort -n | tail -2
done
```

**Expect** p95 well under 2 s on **both**. Baselines measured 2026-08-05 on the largest
campaign (58.2 MB, 4,255 files): **rg 0.01 s**, **Python fallback 0.63 s** — a ~60×
difference that clears the budget either way. Every response prints its own `elapsed_ms`
**and the active scanner**, so a slow answer is explained rather than mysterious.

**The parity invariant — the important half of this scenario:**

```bash
diff <(provenance search "Ilvara" --campaign out-of-the-abyss --limit 500 --scanner rg     --json) \
     <(provenance search "Ilvara" --campaign out-of-the-abyss --limit 500 --scanner python --json) \
  && echo "PARITY PASS: identical results, only elapsed_ms differs"

python -m pytest tests/test_provenance_scanner_parity.py -v
```

Two scanners that disagree produce results that differ by machine — a far worse failure
than a slow scan. Ranking's total-order tail `(campaign, path, line)` is what makes this
diff pass at all: rg is multithreaded and its file order is unstable between runs
(research [D18](./research.md#d18)).

**Forcing an unavailable scanner refuses rather than falling back silently:**

```bash
PATH=/usr/bin:/bin provenance search Ilvara --campaign out-of-the-abyss --scanner rg  # ok here
env -i HOME=$HOME PATH=/nonexistent provenance search Ilvara \
    --campaign out-of-the-abyss --scanner rg; echo "exit=$?"      # expect 1, REFUSED
```

## Scenario 7b — `.gitignore` must not scope the search (research [D17](./research.md#d17))

The single most important correctness check introduced by adopting ripgrep.

```bash
cd ~/src/campaigns

# rg's DEFAULT behaviour — what the feature must NOT do
rg --files -g '*.md' -g '*.txt' -g '*.vtt' -g '*.yaml' -g '*.json' | wc -l     # 11688

# The pinned flag set — what the feature DOES do
rg --files --no-ignore --hidden -g '!.git/**' \
   -g '*.md' -g '*.txt' -g '*.vtt' -g '*.yaml' -g '*.json' | wc -l             # 11914
```

**230 files differ**, 213 of them `Phandalin/docs/npcs/merged_sidecars/**` — working-reference
tier, declared in-scope by the manifest, and invisible under rg's defaults. Prove the
feature sees them:

```bash
provenance search "merged_sidecars" --campaign Phandalin --limit 5
ls ~/src/campaigns/Phandalin/docs/npcs/merged_sidecars/ | head -3
# pick a distinctive string from one of those files and confirm it is searchable:
provenance search "<string from a sidecar>" --campaign Phandalin
```

**Expect** hits from gitignored paths, tagged `working_reference`. A zero result here means
`--no-ignore` was dropped and the search is silently narrower than the manifest declares —
exactly the silent-omission class this feature exists to prevent.

```bash
python -m pytest tests/test_provenance_rg_flags.py -v
```

## Scenario 8 — SC-010 and SC-009, read-only and rebuildable

```bash
cd ~/src/campaigns
find . -type f -not -path './.git/*' -exec sha256sum {} + | sort > /tmp/before.sha

provenance capabilities                              >/dev/null
provenance check                                     >/dev/null
provenance search "Woodland Manse" --campaign Phandalin       >/dev/null
provenance search Ilvara --campaign out-of-the-abyss --expand-aliases >/dev/null
provenance resolve Vera --campaign obelisk           >/dev/null
provenance resolve Harshnag --campaign stormgiants   >/dev/null

find . -type f -not -path './.git/*' -exec sha256sum {} + | sort > /tmp/after.sha
diff /tmp/before.sha /tmp/after.sha && echo "SC-010 PASS: zero writes"
git status --porcelain | head          # expect empty
```

**SC-009** is satisfied by construction: the feature derives no artifact, so there is
nothing to delete and rebuild. Both authored documents are hand-written **inputs**, not
derived outputs. The static guards make this permanent:

```bash
python -m pytest tests/test_provenance_readonly.py tests/test_provenance_no_llm.py \
                 tests/test_layering.py tests/test_retrieve_render_isolation.py -v
```

## Scenario 9 — Story 3's Independent Test (P3), trustworthy empty results

```bash
provenance capabilities
```

**Expect** on this host: all six campaigns enumerated with manifest / identity-store /
corrections status; the resolved workspace root **and which rule resolved it**;
`literal AVAILABLE impl=rg 15.1.0`; and
`semantic  UNAVAILABLE  mempalace not importable on this host` — explicitly distinct from
"available, returned nothing" (SC-004). Every search response repeats the roster under
`backends_consulted`, so a result set is never implied complete (FR-022).

The same command on the WSL2 desktop, where MemPalace *is* installed, must report
`semantic AVAILABLE` — the probe is real, per machine, not a constant
(research [D15](./research.md#d15)).

## Scenario 10 — the MCP seam (Phase 3)

```bash
grep -A3 '"provenance"' ~/src/campaigns/.mcp.json     # no --campaign-dir, no CAMPAIGN_DIR
provenance_mcp --help                                  # server starts unpinned
python -m pytest tests/test_provenance_mcp.py -v
```

**Expect**: the registration block carries **no campaign binding** — that absence is the
feature (research [D4](./research.md#d4)). `test_provenance_mcp.py` asserts every MCP tool
has an exactly equivalent CLI invocation (Constitution VI) and that no tool on this server
writes.

In a Claude Code session opened at `~/src/campaigns`, `provenance_search("Woodland Manse",
campaigns=["Phandalin"])` returns labeled hits, and `provenance_search("Woodland Manse")`
with no `campaigns` is refused — without editing `.mcp.json` or restarting the session,
which is the whole point.

## Full suite

```bash
python -m pytest tests/ -q
```

Live-corpus tests skip cleanly when `~/src/campaigns` is absent (CI, a fresh clone, a
worktree). Contract tests over `tests/fixtures/provenance/` always run — they are what make
the acceptance surface independent of a corpus that drifts between sessions.

> **Worktree caveat** (from prior experience in this repo): the editable-install `.pth`
> can point at the main checkout, so `import provenance` in a worktree may resolve to
> `main`'s copy. A green worktree run is not proof you tested this branch — check
> `python -c "import provenance; print(provenance.__file__)"` first.
