# Contract: `provenance` CLI

**Console script**: `provenance = "provenance.cli:main"`
**Constitution**: VI (CLI is the Engine) — this is the engine; the MCP server is a face over it
**Requirements**: FR-001–FR-026, FR-031, FR-033

Four subcommands. Every one is read-only, deterministic, and makes no LLM call.

```
provenance search   <query> --campaign NAME [--campaign NAME …] [filters]
provenance resolve  <surface-form> --campaign NAME
provenance capabilities
provenance check    [--campaign NAME …]
```

**Exit codes**: `0` success · `1` refusal (missing scope, no manifest entry, no horizon
marker) · `2` argparse/usage error · `3` load error (malformed manifest or corrections).

Refusals are exit `1`, not `0` with an empty list. A scriptable caller must be able to tell
"refused" from "found nothing" without parsing prose — this is Story 3's principle applied
to the shell.

---

## `provenance search`

```
provenance search <query>
    --campaign NAME            # REQUIRED, repeatable. No default. No "all" token.
    [--tier TIER …]            # filter; suppressed hits are COUNTED, never dropped silently
    [--horizon N]              # refused if the campaign declares no horizon marker
    [--expand-aliases]         # explicit opt-in (FR-019)
    [--regex]                  # default: the query is escaped and matched literally
    [--case-sensitive]
    [--limit N]                # default 50; truncation is reported
    [--context-lines N]        # default 2
    [--json]                   # machine-readable; identical data to the text form
    [--campaigns-root PATH]    # overrides $CAMPAIGNS_ROOT and the built-in default
    [--scanner rg|python]      # force one implementation; default = rg if discoverable
```

`--scanner` exists for the parity test and for diagnosing a suspected scanner
disagreement. It does not change results — that is the invariant
`test_provenance_scanner_parity.py` enforces — only latency (~60×). Forcing `rg` when it is
not on `PATH` is a **refusal**, not a silent fallback.

### `--campaign` has no default, at any layer

Not in argparse, not in the model, not in the MCP tool. Omitting it is a **refusal**, and
the message enumerates the known campaigns so the caller re-issues explicitly:

```
$ provenance search "Woodland Manse"
REFUSED: no campaign scope given.

  Search requires an explicit --campaign. There is no implicit "all campaigns".

  Known campaigns: Hillsfar, Phandalin, obelisk, out-of-the-abyss, stormgiants, toee

  e.g.  provenance search "Woodland Manse" --campaign Phandalin
$ echo $?
1
```

There is **no `--all-campaigns` flag in increment 1.** Constitution X permits a
"select all" that materializes the full set as a deliberate act, but Story 5 (cross-campaign)
is P5 and ships last; until then the deliberate cross-campaign act is naming N≥2 campaigns
by hand. SC-003 — "there is no input that causes the system to search all campaigns
implicitly" — is then true by construction rather than by careful defaulting.

### Refusals

| Condition | Message | Requirement |
|---|---|---|
| No `--campaign` | Above | FR-006, SC-003 |
| Campaign not in the manifest | `REFUSED: 'foo' has no manifest entry. Known campaigns: …` | FR-009 |
| Manifest `root` missing on disk | `REFUSED: campaign 'foo' declares root 'foo' which does not exist on this machine.` | Story 3 |
| `--horizon` with no manifest marker | `REFUSED: campaign 'Hillsfar' records no horizon marker; a horizon filter cannot be applied.` | FR-025 |
| Malformed manifest/corrections | `LOAD ERROR: …` + the pydantic path, exit 3 | FR-030 |

**SC-008 is a property of this layout**: tier, generated-by, and correction are on the
frame of every hit, so the reader identifies a stale source without opening the file and
without consulting `CLAUDE.md`. **FR-004 is why the correction is inside the box** rather
than in a footer the caller may not read.

### Suppression is never silent (FR-011, FR-012, SC-005)

```
$ provenance search "Woodland Manse" --campaign Phandalin --tier authoritative

Phandalin — 721 matches, 12 shown, 709 SUPPRESSED BY TIER FILTER  ·  0.01s
  suppressed: working_reference 402 · search_accelerator 218 · staging 89
  excluded by manifest `exclude` globs: 0 files
```

`excluded by manifest exclude globs` is always printed, including when it is `0`. Research
[D17](../research.md#d17) made `exclude` the single scope authority, which concentrates the
risk in one place: one glob added by a GM would otherwise narrow every future search with
nothing in any response to show for it. Tier and horizon suppression are counted, so
exclusion is counted too.

And when a filter excludes everything, the answer is a count, not an empty result:

```
$ provenance search "Grannoc" --campaign Phandalin --tier authoritative

Phandalin — 12 matches, 0 shown, ALL 12 SUPPRESSED BY TIER FILTER  ·  0.14s
  suppressed: working_reference 12
```

### `--json`

Emits `SearchResponse` (data-model.md §12) verbatim. Every hit carries the complete
envelope key set — `null` where there is nothing to say, never an omitted key. SC-001 is
asserted structurally against this shape.

## `provenance resolve`

```
provenance resolve <surface-form> --campaign NAME [--json] [--campaigns-root PATH]
```

Three outcomes, never collapsed into two (FR-017, FR-018):

```
$ provenance resolve Ilvara --campaign out-of-the-abyss
RESOLVED  Ilvara → Ilvara Mizzrym  (npc)
  aliases:           Ilvara, Mistress Ilvara
  known confusions:  (none recorded)
  known-wrong variants: NOT RECORDED BY SCHEMA — the entity registry has no field
                        for wrong variants; misspellings are stored as ordinary
                        aliases and are indistinguishable from legitimate ones.
  note: senior drow priestess
```

```
$ provenance resolve Vera --campaign obelisk
NOT FOUND IN IDENTITY STORE
  obelisk has an identity store (docs/entity_registry.yaml) and 'Vera' is not in it.
  This is NOT a claim that no such entity exists — only that no alias link is recorded.
  No canonical form is guessed from name similarity.
```

```
$ provenance resolve Harshnag --campaign stormgiants
NO IDENTITY STORE FOR THIS CAMPAIGN
  stormgiants declares no entity registry and no aliases file.
  This answer is distinguishable from both a match and a miss.
```

Known confusions, when recorded, are printed as non-identity assertions:

```
$ provenance resolve Topsy --campaign out-of-the-abyss
RESOLVED  Topsy → Topsy  (npc)
  known confusions:
    ✗ Topsy is a DISTINCT entity from Turvy  (registry: distinct)
```

**FR-016 is a property of the implementation, not the wording**: nothing in
`provenance/identity.py` computes a string distance in order to *assert* a match. Near-duplicate
surfacing is `registry check`'s separate, human-gated job and never feeds a resolution.

## `provenance check`

```
provenance check [--campaign NAME …] [--json] [--campaigns-root PATH]
```

Validates the authored data and reports findings for **GM review**. It never edits
anything and never auto-resolves an ambiguity.

| Finding | Meaning |
|---|---|
| `tier-ambiguous` | A path matched more than one tier's globs; names the winner and the losers (research [D8](../research.md#d8)) |
| `stale-correction-entry` | A correction's `applies_to.paths` match no file on disk — prune it |
| `unclassified-heavy` | A directory where >N% of files match no tier glob — likely a missing glob |
| `horizon-unattributable` | Files under `docs/chapters/` the `path_pattern` cannot attribute |
| `campaign-root-missing` | Declared root absent on this machine |
| `no-identity-store` | Informational; expected for stormgiants and Hillsfar |

Exit `0` when there are only informational findings, `1` when any error-level finding
exists. Mirrors `registry check`'s contract: **report drift for a human to rule on, never
merge or fix autonomously.**

## Workspace-root resolution (Principle VIII)

`--campaigns-root` → `$CAMPAIGNS_ROOT` → `campaignlib.constants.CAMPAIGNS_ROOT`
(`~/src/campaigns`). Which rule fired is reported by `capabilities`.

The constant currently exists as a bare literal at
`pipelines/workspace/configure_mcp.py:44`; this feature **moves it to
`campaignlib/constants.py` and refactors `configure_mcp` to import it**, so there is one
answer rather than two literals that can drift (research [D5](../research.md#d5)).

## Scanner selection

`--scanner` → `rg` if `shutil.which("rg")` resolves → `python`. Reported by `capabilities`
and in every search response header.

The two implementations are required to return **identical** hit sets;
`test_provenance_scanner_parity.py` asserts it over the fixture workspace and one live
campaign. rg is ~60× faster (0.01 s vs 0.63 s on the largest campaign) and that is the
only difference a caller should ever observe.

**The rg flag set is pinned and test-guarded** (`test_provenance_rg_flags.py`). Three of
those flags exist for correctness, not speed, and are worth knowing before anyone edits
the invocation:

| Flag | Consequence of omitting it |
|---|---|
| `--no-ignore --hidden` | **230 real files silently vanish** from this workspace — 213 Phandalin NPC sidecars, plus `toee/temple/wiki/**` and `stormgiants/Storm King Thunder/wiki/**`, all working-reference tier. `.gitignore` is a version-control concern and has no vote on what is true on disk (research [D17](../research.md#d17)) |
| `--no-config` | `$RIPGREP_CONFIG_PATH` could inject `--smart-case` or extra globs, changing results per machine. Unset on this host — which is why it is pinned rather than assumed |
| `--json` | Paths and prose in this corpus contain `:` and spaces; `path:line:text` parsing is a latent bug. `--json` also defines the non-UTF-8 case instead of raising mid-scan (research [D18](../research.md#d18)) |

Never `--smart-case`: it would make `Ilvara` and `ilvara` search differently based on the
query's own casing.
