# Contract: Narration Bundle Run Report

**Feature**: 022-bundle-narration | Governs FR-013, FR-014, FR-018, FR-019, FR-021

## 1. Location and lifecycle

`sd_narrate --batch-scenes` writes UTF-8 JSON atomically before exiting. The default is:

```text
<per-scene-output>/logs/sd_narrate_bundle_latest.json
```

`--run-report FILE` selects another path.

For standalone CLI use, the default `latest` path is replaced on each attempt and the CLI generates the `run_id`. With an explicit `--run-report`, the report filename stem is the `run_id`. The editor never uses the shared path: it generates an unguessable nonce as the filename, passes a unique session-local path such as `<session>/.cg/narrate-bundle/<run-id>.json`, and requires the report's `run_id` to match that nonce. The nonce-scoped report remains as chronological run history and prevents concurrent tabs or identical selections from consuming one another's results.

## 3. Validation rules

- `version` is exactly `1`; consumers reject unknown versions rather than guessing.
- `run_id` is a non-empty invocation identifier. It is generated by the CLI for the default report path and equals the filename stem for an explicit `--run-report`; the editor therefore requires its server-generated filename nonce.
- `mode` is exactly `bundle`.
- `status` is one of `success`, `partial`, `unreconcilable`, `refused`, `failed`.
- `exchange_count` is `0` or `1` and is `0` only when no model call started.
- `requested` preserves explicit full-plan order and has unique positive indices.
- `replaced` is a subset of `requested` selected by pre-call `output_existed`.
- `written` is a subset of `requested` produced by this invocation, never inferred from file presence.
- `missing` contains requested scene identities with `reason` equal to `empty`, `incomplete`, or `absent`.
- `rejected` contains structured issues with `code`, `message`, and optional `index`/`path`.
- `success` means `written` equals `requested` and exit `0`.
- `partial` means fewer than all requested scenes were safely written and at least one scene is classified `empty`, `incomplete`, or `absent`, exit `3`. `written` may be empty when the response is structurally valid but has no writable body.
- `unreconcilable` means exit `4` and `written` is empty.
- `refused` means exit `1`, exchange count `0`, and `written` is empty.
- `failed` means exit `1`; exchange count states whether the backend call started.
- Every terminal refusal or backend exception is caught and represented as `refused` or `failed` before exit, provided the report destination itself was initialized successfully.

## 4. Editor consumption

The editor streams the child with `stream_subprocess(..., emit_done=False)`. After that generator completes, the route reads the exact nonce-scoped report and validates its version, `run_id`, raw return code, and requested indices against the server-owned invocation state. It then:

1. writes the current knob snapshot beside each path in `written`;
2. records one `stage: narrate` activity row using report-derived outputs and counts;
3. leaves pre-existing files named only in `missing` or `rejected` untouched and does not update their sidecars;
4. emits one route-specific `event: done` payload containing `returncode`, `status`, `run_id`, `written_count`, `requested_count`, `missing`, `rejected`, and any bounded report-validation error so the UI can distinguish success, partial, unreconcilable, refusal, and backend failure.

A missing, invalid, nonce-mismatched, return-code-mismatched, or selection-mismatched report is itself recorded as an audit failure; the route never infers successful outputs from files that happen to exist. The route emits its custom terminal event only after report validation, sidecars, and activity recording finish.
