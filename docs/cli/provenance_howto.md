# Provenance search — how-to

**Command:** `provenance` · **MCP server:** `provenance_mcp` · **Spec:** `specs/007-cross-campaign-search/`

This is the task-oriented page: *"I want to do X, what do I type."* Its companion,
[`provenance_search.md`](provenance_search.md), is the reference — the manifest and
corrections **schemas**, every `check` finding, the field-by-field envelope. When the two
overlap, the reference wins.

Read this one when you are trying to get an answer out of the corpus. Read the reference
when you are about to hand-edit `provenance.yaml` or a `corrections.yaml`.

---

## What this actually is

You have six campaigns under `~/src/campaigns`. Mixed together in them are session
summaries the GM wrote, VTT transcripts of what was actually said at the table, grounding
docs a pipeline generated last Tuesday and will overwrite next Tuesday, half-finished
notes, and a handful of documents that are **known wrong** and have been for weeks.

`grep` returns all of that as flat text. That is not a search problem, it is a trust
problem, and it has already bitten: a consistency check read `docs/world_state.md` as
canon and flagged a *correct* recap as a continuity error, because nothing in the output
said "a pipeline wrote this line and the GM has recorded that it is wrong."

So every hit comes back wrapped in a **provenance envelope**:

```
┌─ [2] WORKING REFERENCE  ·  chapter 43  ·  ai-assisted
│  docs/world_state.md:9
│  ⚠ GENERATED BY `distill` — will be clobbered on regeneration
│  ⚠ KNOWN STALE — correction `woodland-manse-empty`
│
│  →   …the party is now returning from Falcon's Hunting Lodge…
│
│  ▸ CORRECTION `woodland-manse-empty` (recorded 2026-08-04, as of chapter-43)
│    STALE CLAIM: "Active; Grannoc performing ritual; NOT visited."
│    TRUTH:       The Woodland Manse has been empty since Chapter 43.
└─
```

Tier, generating stage and correction are on the **frame**, so you know not to trust the
line before you have finished reading it. That is the whole product. It reads only —
never writes, never touches identity data, never calls a model.

---

## Before anything else: is it wired up here?

```bash
provenance capabilities
```

Tells you the resolved workspace root **and which rule resolved it** (`--campaigns-root`
→ `$CAMPAIGNS_ROOT` → the built-in default), the six campaigns with their manifest /
identity-store / corrections / horizon status, and which retrieval backends are live *on
this machine*.

That last part is the point of the command. An empty result from a backend that is not
installed and an empty result from a backend that looked and found nothing are the same
two words on your screen and opposite next actions. `capabilities` is how you tell them
apart before you go rewrite a query that was fine.

## The five things you will actually do

### 1. Find a fact, and know whether to trust it

```bash
provenance search "Woodland Manse" --campaign Phandalin
```

`--campaign` is required and repeatable. There is no `--all`, no `*`, no default — omit it
and you get a **refusal (exit 1)** listing the campaigns, not a search of all six.

Read the header first. It tells you what you are *not* seeing:

```
Phandalin — 724 matches, 50 shown (limit), 0 suppressed  ·  0.06s  [scanner: ripgrep 15.1.0]
  withheld by --limit: 674
  excluded by manifest `exclude` globs: 0 files
  backend literal: available (contributed: yes)
  backend semantic: unavailable — mempalace is not importable on this host
```

Then read the tier on each hit. `AUTHORITATIVE` is the table's own record. `WORKING
REFERENCE` is usually pipeline output. `STAGING` is `notes/` — unreviewed, and never
canon. `UNCLASSIFIED` means no glob in the manifest claims that path; the file is still
returned, labelled, because dropping it would be a narrowing nobody could see.

> **One thing to know up front.** Relevance is *matches-in-this-file* plus small bonuses,
> so a single large file can fill the whole page — `search Calmer --campaign toee` returns
> 200 hits and all 200 are from one ensemble artifact. Nothing is hidden (the header says
> how many were withheld), but see [When results look wrong](#when-results-look-wrong)
> below. Tracked in [#242](https://github.com/kostadis/CampaignGenerator/issues/242).

### 2. Search only the material you trust

```bash
provenance search "Grannoc" --campaign Phandalin --tier authoritative
```

Suppressed hits are **counted, never silently dropped**:

```
Phandalin — 124 matches, 14 shown, 110 suppressed
  suppressed by tier filter: search_accelerator 15 · staging 53 · unclassified 21 · working_reference 21
```

If a filter removes everything you get `hits: []` **with** the counts — `ALL 12 SUPPRESSED
BY TIER FILTER`, not a bare empty list. "I found nothing" and "I found twelve things and
hid them from you" are different answers.

### 3. Ask what was true as of chapter N

```bash
provenance search "the Manse" --campaign Phandalin --horizon 43
```

Chapter comes from a filename pattern the manifest declares per campaign — never from
reading the file. Anything later is excluded and counted. A file the pattern cannot
attribute (`docs/chapters/appendix_unnumbered.md`) comes back labelled
`⚠ chapter unattributable` rather than being dropped, because it cannot answer your
question either way.

A campaign that declares no horizon marker **refuses** the query instead of serving it
unfiltered. Answering "what was true at chapter 43" with the whole present-day corpus is
the worst available failure: confident, complete-looking, and full of the spoilers you
asked to exclude.

### 4. Work out which name is which

```bash
provenance resolve Ilvara --campaign out-of-the-abyss
provenance resolve Vera   --campaign obelisk
provenance resolve Anyone --campaign stormgiants
```

Three outcomes, never collapsed into two:

| Output | Means | What to do |
|---|---|---|
| `RESOLVED  X → Y` | A GM recorded this link | Use `Y` |
| `NOT FOUND IN IDENTITY STORE` | The store exists; nobody recorded this name | Consider `registry alias` |
| `NO IDENTITY STORE FOR THIS CAMPAIGN` | stormgiants and Hillsfar have none | Nothing to record against |

Recorded confusions print as explicit non-identity assertions:

```
✗ Kazneporium Ketternopappux is a DISTINCT entity from Kostadinious the Sage  (registry: distinct)
✗ Topsy is a DISTINCT entity from Turvy  (registry: distinct)
```

**Nothing here guesses from spelling.** `Vera` did not resolve to `Veyra` for months, even
though the files sat next to each other, because no human had written the link down.
Making it resolve took a `registry` command run by the GM — not a similarity threshold.
That is deliberate: name similarity is the single most convincing way to merge two people
who are not the same person.

To search every recorded spelling at once:

```bash
provenance search Ilvara --campaign out-of-the-abyss --expand-aliases
```

Each hit reports the `matched_surface_form` that found it, and duplicates collapse to the
longest form so the label names the most specific match.

### 5. Compare two campaigns

```bash
provenance search "Talos" --campaign Phandalin --campaign stormgiants
```

Naming two or more campaigns **is** the deliberate cross-campaign act; there is no token
for it. Hits stay labelled with their owning campaign and are never merged — two games
with a same-named NPC keep them apart, because nobody has said they are the same.

## From a Claude session instead of a shell

The `provenance` MCP server is registered in `~/src/campaigns/.mcp.json` and is the **only
unpinned server there**. Every other one — `campaign`, `5etools`, `registry` — binds a
campaign at process start, so asking about a different game means editing that file and
restarting. This one takes no campaign argument at all:

```json
"provenance": { "command": "provenance_mcp", "args": [] }
```

Four tools, all read-only: `provenance_search` (scope required, no default, empty list
refused), `provenance_resolve`, `provenance_capabilities`, `provenance_check`. Each is a
thin wrapper over the CLI, so the two cannot drift — every tool has an exactly equivalent
shell command.

Nothing on this server writes. Identity changes stay with `registry_mcp`, behind explicit
confirmation.

## When results look wrong

**One file filled the whole page.** Expected on broad queries — relevance counts matches
per file. Fixes, cheapest first: add `--tier authoritative`, lengthen the query, or add an
`exclude` glob to the manifest for a machine artifact that is only in scope because
`.json` is a searchable extension. ([#242](https://github.com/kostadis/CampaignGenerator/issues/242))

**A hit I expected is missing.** Check the header. `withheld by --limit`, `suppressed by
tier filter`, `suppressed by horizon` and `excluded by manifest exclude globs` are all
printed on every search — including at zero. If all four are zero, the string genuinely is
not in that campaign.

**A file I know is there never comes back.** `.gitignore` does **not** scope this search —
230 `.gitignore`d files in the workspace are searched deliberately. Scope comes only from
the manifest's `search_extensions` and `exclude`. Run `provenance check <campaign>` and
look for `unclassified-heavy`.

**Everything is `unclassified`.** The manifest declares no tier globs covering that
directory. It is a labelling gap, not a suppression — the files are still returned. `check`
reports the heavy directories.

**It refused instead of answering.** Refusals are exit `1` and always say why. The four
you will meet: no `--campaign`; a campaign name not in the manifest; a declared campaign
root missing on this machine; `--horizon` against a campaign with no marker.

**It exited 3.** A hand-authored file is malformed. The message carries the pydantic path.
Loading is all-or-nothing on purpose — a half-loaded manifest would answer "which
campaigns exist" wrongly, and everything else is built on that answer.

## Keeping it healthy

```bash
provenance check                      # all six
provenance check --campaign toee      # one
```

Reports drift for you to rule on and **never edits anything**. Exit `0` with
informational findings is the normal state; exit `1` means at least one error-level
finding. Current baseline: **15 findings, 0 error-level.**

The ones you will see most: `unclassified-heavy` (a directory with no glob),
`stale-correction-entry` (a correction pointing at a file that no longer exists — prune
it), `unverified-correction` (a `verified: false` entry awaiting your ruling),
`tier-ambiguous` (two tiers claim the same paths; first-match-wins is applying).

Full table of all ten, and what to do about each, in
[`provenance_search.md` §8](provenance_search.md).

---

## The rules it will not bend

- Never writes to campaign content, ever. Guarded by an AST sweep plus a before/after
  sha256 of the whole fixture workspace.
- Never mutates identity data — that stays with `registry`, behind your confirmation.
- Never calls a model. Guarded by an AST sweep; there is no ranking or summarisation you
  cannot reproduce by reading the same files.
- Never merges entities across campaigns.
- Never infers the authored data. The manifest and corrections files are hand-written or
  they do not exist.
- Never defaults scope to "all".
- Never lets `.gitignore` decide what is searchable.
