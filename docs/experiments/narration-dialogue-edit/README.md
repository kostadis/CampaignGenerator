# Narration v1 and dialogue-editing experiments

Status: versioned proposals, not active production defaults. No runtime templates, campaign configuration, or source documents are changed by this directory.

## Accepted narration baseline

`narration_v1.md` is the first revised narration brief accepted by the GM after the September 2026 Phandalin trials. It preserves player speech while giving setting, action, and causal connections room in the narration. It removes dialogue quotas and fixed expansion rules. The more restrictive v2 experiment was not selected.

The file is an exact copy of the accepted campaign-local `narration_prompt_test/prompt.md`:

```text
SHA-256 67feb055f9efa13a384c3ae80d7c1b3eac20436c88d418aed2b79482806f2aa6
```

The earlier experimental harness replaced the system prompt in-process, added the declared character perspective and examples, and retained the normal `sd_narrate` user payload. For Phandalin, it extracted the character-specification section from voice files and adjusted three conflicting generic genre instructions locally. For Obelisk, it supplied the full declared voice notes and the campaign register policy. The writing brief alone is therefore not a byte-identical replacement for the entire production prompt stack.

## Proposed next pass

`dialogue_edit_proposal.md` preserves the proposed post-narration editing contract before testing. Its purpose is to make dialogue readable in its surrounding prose without replacing the player's performance with an imitation.

The next experiment compares three approaches on the same existing drafts:

1. Light dialogue copyedit, leaving the narration unchanged.
2. Contextual dialogue editing, allowing limited changes to adjacent attribution.
3. Integrated scene line editing, allowing dialogue and inner prose to be adjusted together.

Use `gpt-6-astra` with medium reasoning for every arm. Each arm starts from the untouched baseline, never from another arm's output. Judge readability, player-dialogue fidelity, narrator's inner voice, and event/knowledge preservation separately. There is no target dialogue ratio or required shortening.

Preserve submitted prompts, raw responses, source hashes, and before/after comparisons. Results are proposed drafts for human review, not edits to the source extractions or voice files. Existing exact-quote diagnostics cannot establish semantic fidelity once editing is explicitly allowed.

Missing-event review remains a separate concern: [CampaignGenerator #386](https://github.com/kostadis/CampaignGenerator/issues/386).

The editing prompts should explicitly resolve inherited verbatim-copy rules for this stage. This follows the instruction-conflict guidance in the [official Astra documentation](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra); it is not evidence that broader editing will preserve a particular player's voice. The test drafts must establish that.

## Running the experiment

`run_test.py` calls the installed CampaignGenerator `campaignlib` adapter; it does not install or activate a new production pipeline. A cases JSON file contains a list of objects with `id`, `narrator`, `scene`, absolute `draft` and `source` paths, and a `references` list of absolute text-file paths. Each case is sent independently to all three approaches. Runtime state records the actual backend module, model selection, hashes, and experiment commit.

```bash
python docs/experiments/narration-dialogue-edit/run_test.py \
  --cases /path/to/cases.json --output-root /path/to/results

# After inspecting the prepared prompts:
python docs/experiments/narration-dialogue-edit/run_test.py \
  --cases /path/to/cases.json --output-root /path/to/results --render --workers 3

python docs/experiments/narration-dialogue-edit/build_reader.py /path/to/results
```

Completed responses and differing snapshots are never overwritten. Use a new output root for another trial. `extract_passages.py` copies the selected passages for the three cases in the initial experiment; its anchors are intentionally specific to those drafts, not a generic passage selector. The prose review is human/assistant-authored after inspecting the diffs, not generated by the diagnostic metrics.

The first nine-call experiment is summarized in [RESULTS.md](RESULTS.md). The full local reader, source context, prompts, responses, and review were saved separately under the main checkout's `worktrees/narration-v1-dialogue-edit-results/`, not committed as campaign content.
